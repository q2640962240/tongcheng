# 「白夜」App — 功能补强规格说明（Spec）

> 仓库根：`d:\tongcheng\companion-play-app` · 运行时：Node 18+ · 移动端：uni-app (Vue 3 + Vite) · 后端：Express + JSON Store · 管理后台：Vue 3 + Element Plus · 素材参考：`sucai/`（10 张竞品截图）

---

## 一、问题陈述

当前产品名为「同城陪伴玩 APP / 伴玩」，与用户真实定位（年轻化、社区化、"白夜"主题的陌生人社交+陪伴消费）不符；且通过对 `sucai/` 同类型产品截图的比对，现有 App 存在以下**关键功能缺口**：

| # | 缺口（相对用户提供的竞品截图） | 说明 |
|---|---|---|
| G1 | 产品名 / 品牌不符 | 所有位置仍显示"伴玩"，未统一到"白夜"；设计体系仍为亮黄 `#ffd60a`，与"白夜"午夜氛围不搭 |
| G2 | 缺"动态 / 广场（发现）"信息流 | 参考图 3「动态」：支持发图文动态、点赞、评论、联系 TA、全国/附近筛选、定位城市、在线状态 |
| G3 | 缺"同城组局 / 拼团玩法"Tab | 参考图 2「同…局」：组局新玩法入口 + 看电影/旅行等卡片 + 报名进群 + 顶部切换（寻人大厅/动态/同城组局/红包专区） |
| G4 | 缺"新人秀 / 最新认证推荐"轮播 | 参考图 1 首页顶部「新秀! 最新认证用户」横向滚动 + 审核中状态 + 关闭按钮 |
| G5 | 精英付费体系弱 | 参考图 4 是「付费开通精英（30/终身）」模式，不是审核模式；含 6 项权限权益 + 开通即时生效 + 100% 真人保障；参考图 5 在详情页弹窗"立即加入/再逛逛" |
| G6 | 个人资料卡 / 详情卡布局差异 | 参考图 1/5 的个人卡：昵称+年龄+职业+城市+期望对象+微信号（打码）+查看按钮 + 语音条（5"）+ 图片瀑布流 + 联系TA + 温馨提示协议 + 精英弹层 |

| G8 | 首页顶部入口不同 | 参考图 1：Banner（净化网络环境横幅）+ Tab（暖心服务/兴趣约玩/同城） |

本规格的目标是**一次性把品牌 + 上述 8 大产品缺口全部补齐**，并输出完整项目说明文档，确保 `白夜` 可直接用于打包与商业功能演示。

## 二、用户画像与目标

- **用户（买家）**：18~30 岁年轻用户，寻找陪伴、游戏陪玩、同城活动、交友；会被新人秀 / 组局 / 动态吸引；希望"高效邀约（参考图 5 弹窗）"。
- **用户（服务者 / 陪玩）**：希望通过认证、发布服务/动态获得订单、加入精英提高曝光。
- **平台运营方**：管理后台能审核动态/组局/精英/反馈、能配置 Banner、能给用户打款。

## 三、功能需求（Functional Requirements）

### R1. 品牌重命名为「白夜」
1. 任何展示/文案层出现的产品名：`伴玩`、`同城陪伴玩`、`同城陪伴`，统一替换为 `白夜`。
2. 设计体系切换为**午夜蓝 + 金色高亮 + 紫极光渐变**，替换旧的亮黄主题。设计 token 必须重新定义且在 uni.scss / pages / 管理后台全站生效。
3. 应用图标、启动图、Manifest 的应用名同步更新为"白夜"（保留 appid `__UNI__B38A42D`）。
4. 配置中心默认站点名、客服协议、隐私协议中的产品名同步更新。

### R2. 「发现」模块（动态广场 + 组局 + 寻人/红包专区）
1. 新增 `discover` 发现页：顶部四 Tab：**寻人大厅 / 动态 / 同城组局 / 红包专区**，默认"动态"。
2. **动态**子页面：
   - 顶部筛选：全国（全部）/ 附近（全部）下拉、城市定位、发布动态按钮。
   - 动态卡片：头像 + 昵称 + 审核标签 + 性别年龄 + 职业 + "当前在线"状态 + 发布时间 + 文本（最多 500 字）+ 最多 9 张图片瀑布流 + "联系 TA"（黄色大按钮）+ 点赞（❤）+ 评论图标 + 更多。
   - 接口：创建动态、列表（分类/距离/分页）、点赞/取消、评论；发布动态需要登录。
3. **同城组局**子页面：
   - 顶部入口 Banner（组局新玩法 + "立即加入"跳精英认证付费弹窗）。
   - 组局卡片：图标（电影/旅行/🎬🌴）+ HOT 角标 + 标签（电影/约会/恋爱）+ 描述 + 期望人数 + "报名进群"按钮。
   - 顶部筛选：城市、期望人数、活动时间、发起组局。
   - 接口：组局 CRUD、报名、取消、发起人确认。
4. **寻人大厅**：列表模式（按「最新/匹配度/距离」排序），点击进个人详情。
5. **红包专区**：浏览平台活动 / 任务领钻（后续可接入真实支付红包，第一期静态+模拟）。

### R3. 首页（白夜首页）改版
1. 顶部 Banner：`净化网络环境 传播网络正能量` 图 + 引导举报。
2. 顶部三个快捷入口：**暖心服务 · 兴趣约玩 · 同城**。
3. 「新秀! 最新认证用户」横向轮播：头像 + 审核中徽标 + 关闭按钮 + 滚动动画。
4. 以下内容瀑布流：**用户资料卡（参考图 1 梓晴样式）**。资料卡包含：
   - 头像 + 昵称 + ♀年龄 + 职业 + 城市 + 发布时间
   - 💕 期望对象（一行描述）
   - 💬 微信号 打码（L\*\*\*\*0）+「查看」按钮（点击需解锁：精英用户 / 钻石扣减）
   - 3 张正方形图片瀑布流
   - 兴趣标签：兴趣约玩·运动健身
   - 一句话自我介绍
   - 「联系 TA」按钮（黄底黑字圆角）+ 语音条（5"，点击播放）
   - 温馨提示协议卡片
   - 精英弹层（点击联系TA，非精英弹出：立即加入 / 再逛逛）

### R4. 精英付费体系（替代"审核式精英"）
1. 价格：30 元 / 终身（人民币，后台可配置）。
2. 权益卡片：6 项（暖心服务解锁 / 寻人大厅发布 / 兴趣交友赠 10 次 / 聊天无限聊 / 快速邂逅 / 专属 E 标）。
3. 支付后**即时开通**，无需人工审核；后台仍可封禁/撤回。
4. 详情页"联系 TA"未解锁强制弹窗：「立即加入 / 再逛逛」（参考图 5）。
5. 历史「审核式精英申请」接口保留（兼容管理后台），但 App 侧入口切换为付费开通；审核接口改为支付入账回调后自动通过。

### R5. TabBar 4 Tab + 消息入口独立
1. TabBar 固定 4 项：**首页 / 发现 / 消息 / 我的**，图标与选中态对齐「黄色实心、白色未选中描边」参考图 3。
2. 发现页路由 `/pages/discover/discover`、消息保留 `/pages/chat-list/chat-list`。

### R6. 后端 & 管理后台补齐（与 R2/R3/R4 一一对应）
1. 新增模型：`Post`（动态）、`Comment`（评论）、`Group`（组局）、`GroupJoin`（报名记录）、`Banner`（Banner）、`EliteOrder`（精英付费订单，与 Wallet 挂钩）。
2. 路由：`/posts`（CRUD+点赞+评论）、`/groups`（CRUD+报名）、`/banners`（后台管理）、`/elite/pay`（下单+回调+立即开通）。
3. 管理后台增加 4 个新 Tab：**动态管理（审核/删除）、组局管理、Banner 管理、精英订单**，并在仪表盘加动态数、组局数指标。
4. 配置中心新增：精英终身价、查看微信号扣钻数量、新人秀展示数量、首页 Banner 图。

### R7. 素材目录落地到静态资源
1. 从 `sucai/` 选取：
   - 1 张作为登录页背景、1 张作为默认首页 Banner 占位、3 张作为动态示例配图、2 张作为组局示例配图。
   - 复制到 `app/src/static/sucai/` 与 `server/uploads/sucai/`，保证 H5 / App / 管理后台都可访问。
2. 示例数据（`npm run seed`）补：30 条动态、8 个组局、2 个 Banner。

### R8. 项目文档 & 说明同步
1. README.md：标题与介绍换成「白夜」、列出新功能（动态/组局/新人秀/发现/精英付费）。
2. PROJECT.md：核心功能清单从 41 项扩展至 55+ 项，新增"发现广场 / 组局 / 动态 / Banner / 精英付费 / 微信查看解锁"等条目；Phase 6 新增「白夜 v2 品牌升级」里程碑；设计规范改为午夜蓝 + 金色 + 极光渐变。
3. PRIVACY-POLICY.md：产品名替换 + 新增"动态/组局/地理位置"相关收集说明。
4. APP-STORE-CHECKLIST.md：新增"动态内容审核""组局举报""精英付费（非应用内购买说明）"的上线自检项。
5. docs/ 目录新增：`BRAND-REFERENCE.md`，记录 sucai 每张参考图对应实现了哪些页面/组件/接口，作为交接文档。

## 四、非功能需求

### NF1. 兼容与不破坏
- 旧 API 不删除，只新增；现有 8 Jest / 71 E2E 测试必须 100% 通过（含旧订单、钱包、服务、聊天接口）。
- 旧精英认证 URL 仍可访问；自动重定向或弹窗提示新付费模式。
- 管理后台保留原有所有页面；只新增 4 个 Tab，不删字段。

### NF2. 性能
- 动态/组局分页：首屏 10 条内返回 <200ms（本地 JSON Store，QPS ≥ 150，沿用 bench.js 测量）。
- 首页资料卡瀑布流：单页图片 ≤ 18 张；静态资源压缩后 ≤ 80KB/张（WebP 优先）。

### NF3. 安全 & 合规
- 动态发布 & 评论：后端对 XSS / 敏感词（至少 30 个常见敏感词正则黑名单）过滤。
- 精英付费订单：回调签名校验；幂等（同一 outTradeNo 只入账一次）。
- 联系 TA、查看微信号：次数限制（非精英：0 次；精英：每天 ≤ 50 次；钻石查看每次扣钻，余额不足返回错误码）。

### NF4. 测试
- 新增 Jest 套件：`post.test.js`、`group.test.js`、`elite-pay.test.js`、`banner.test.js`，至少 18 个用例。
- E2E 追加 12 个用例：动态 CRUD、点赞评论；组局报名、取消报名；精英付费开通 + 自动解锁联系 TA + 扣钻查看微信号。
- 所有修改完成后：Jest 全部通过；E2E 通过 ≥ 95%；后端健康检查 OK。

### NF5. 打包 & 交付
- 重新生成 HBuilderX 图标与启动图：logo 采用"白"+"夜"首字母 B 渐变 + 午夜蓝底；TabBar 四图标（首页/发现/消息/我的）默认与选中态都补齐 PNG 81×81。
- manifest.json / pages.json 合法；HBuilderX 打开不报错。

## 五、约束、假设与依赖

1. 约束：`sucai/` 目录图片仅作参考，不可直接商用上线；示例数据仅用于打包演示；生产上线必须替换为自有版权图片。
2. 假设：现有 JSON Store 容量足够（当前 10 张图 + 30 条动态 + 8 组局 + 2 banner + 5 测试用户 × 若干交易）。
3. 依赖：用户已安装 HBuilderX 用于打包；后端在 localhost:3000 保持运行；微信/支付宝真实支付可继续 dev 回退。
4. 约束：本次不拆分包、不换框架、不改 appid、不引入 MySQL/Redis。
