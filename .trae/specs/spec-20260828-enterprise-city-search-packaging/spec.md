# 规格：白夜 App 企业级定位 / 搜索全量兜底 + 打包可交付（Spec Mode）

## 1. 问题、用户与目标
### 问题
当前企业级运营交付前仍存在 3 类不可接受缺口：
1) **定位 / 城市选择覆盖不足**：现有 `city.vue` 仅内置少量示例城市 + 37 个经纬度→城市映射，无法支撑**全国所有地级市**（约 333 个地级行政单位 + 4 直辖市 + 31 省份/自治区/特区完整分区）的选择与检索；定位失败、拒绝授权、精度不足等场景**没有多层兜底**，导致用户选择不到自己城市。
2) **前端功能兜底缺失**：用户端首页 / 搜索 / 发现 / 订单 / 钱包 等关键链路，接口失败、未登录、数据为空、数据类型异常（非数组/对象）时**未做类型收敛**；企业级运营要求页面不崩、不给用户"undefined"式体验。
3) **打包能力未闭环**：仅说明过 HBuilder X 打包步骤，但本项目尚未执行过**可复现的 H5 / 微信小程序 / App 本地构建产物校验**；企业交付必须确保 `dist` 目录结构、入口文件、配置引用路径都按 HBuilder X / 目标端的规范输出。

### 用户
- C 端用户（H5 / 微信小程序 / Android / iOS App）
- 运营人员（需在后台上架新城市、做全国数据）
- 交付/运维人员（需稳定打包、一键启动三端）

### 目标
- **全国地级市完整覆盖**：城市选择页/首页定位/后端筛选统一为「省→市」两级数据，含 34 个省级单位 + 全部地级及以上城市，按运营标准使用民政 2024 版行政代码体系；不允许"随便加几个城市"。
- **多层兜底定位**：`uni.getLocation + 高德/腾讯 WebAPI（配置中心密钥）+ 本地 IP 粗定位（后端回退）+ 用户手动选择（最后保障）` 共 4 级，每一级失败都**不抛到用户**，自动降级；企业级容错，永远有一个城市值可用。
- **前端全链路兜底**：首页 / 搜索 / 发现 / 订单列表 / 钱包 / 个人中心 7 大场景全部做：①未登录降级 ②空态图+引导 ③接口异常 toast + 可重试 ④ `Array.isArray / isObject` 类型收敛；任何接口失败不导致崩溃。
- **打包闭环验证**：在本机用 HBuilder X CLI（或同等构建管线）产出至少一套**可部署的 H5 dist** 和一套**微信小程序输出目录**，并通过目录结构 / 关键文件存在性 / 基础资源可访问性 做自动校验，交付前留证据。
- **文档同步**：`README.md`、`PROJECT.md`、`.env.example` 同步说明新的定位策略、打包命令与验证步骤、全国城市数据集来源；继续保持 PROJECT_MEMORY 的同步约束。

## 2. 非目标（排除范围）
- 本次不引入新的数据库（继续沿用 JSON 文件存储层的扩展能力）
- 不重写 uni-app 打包管线本身，仅在现有 HBuilder X/ Vite plugin-uni 之上做构建和校验
- 不开发 PC Web 端后台新功能模块（沿用现有管理后台，仅增补必要配置）

## 3. 功能需求（Functional Requirements）

### FR-1 全国地级市数据集（企业级）
- **FR-1.1**：项目内置一份全国行政区划数据集 `server/src/data/china_cities.json`（或同路径 JS 模块），内容为：
  - 34 个省级行政区（省 / 直辖市 / 自治区 / 特别行政区）：含 `code`（6 位区划代码）、`name`、`spell`（拼音首字母/全拼，供字母索引用）；
  - 对应每个省下的所有**地级及以上城市**：含 `code`、`name`、`provinceCode`、`provinceName`、`spell`、`alias`（别名/旧称，搜索时可命中）；
  - 数据来源：以中华人民共和国民政部 2024 年《县以上行政区划代码》为准（版本标记写入数据集元信息）；总数应 ≥ 333 地级市 + 4 直辖市 = 337 个地级及以上城市；省级数必须为 34。
- **FR-1.2**：后端新增 `GET /api/regions/tree` 返回「省→市」两级树，用于初始化城市选择页；另提供 `GET /api/regions/search?kw=` 做中文/拼音/别名模糊检索。
- **FR-1.3**：后端 `services / posts / groups / user.discover` 所有带 `city` 过滤的接口，在**无法匹配到精确城市**时，允许降级到"包含关键词前缀"匹配（例如用户输入"广州"→同时匹配"广州市"、历史旧值"广州"）。

### FR-2 多层定位降级（企业级容错）
- **FR-2.1**：用户端新增 4 级定位流水线，按顺序执行，任一成功即返回；全部失败走「上次选择的城市 / 默认城市」最后兜底，**永远返回合法 cityName**：
  1) 端内 `uni.getLocation`（支持 `gcj02`）→ 调用后端 `POST /api/location/reverse`（配置中心 `app.geoProvider` + `app.geoKey`）做经纬度逆地理；
  2) 前端 `IP 回退`：调用后端 `GET /api/location/guess-by-ip`，服务器按 `X-Forwarded-For / remoteAddress` 做本地 IP 粗分，返回省份+省会/热门候选；
  3) 前端「请求开启定位权限」引导：若用户拒绝或系统关闭，引导到系统设置页（H5 降级跳城市搜索）；
  4) 用户在城市选择页手动选择（永远可用）。
- **FR-2.2**：`app.geoProvider` 支持 `amap|tencent|off` 三值；当为 `off` 或密钥为空时，第 1 级自动跳过并返回提示"定位服务暂未配置，已切换到手动选择城市"。
- **FR-2.3**：`city.vue` 字母索引从 A~Z 对**全国所有城市**分组生成；空字母不展示；点击字母滚动到对应区域；同时支持顶部搜索框跨中文/拼音/别名命中。
- **FR-2.4**：用户切换城市后：①写入 `baiye_city` 持久化 ②首页 `services` 列表按新城市过滤重新加载 ③发现页 `寻人大厅/组局/红包` 所有 Tab 的城市 picker 同步刷新。

### FR-3 搜索后端扩展（企业级质量）
- **FR-3.1**：`GET /services?keyword=…` 扩展为支持「城市 + 关键词」联合检索，空城市时走全国；并增加**同义/别名映射**（如 "LOL" = "英雄联盟"、"撸啊撸" = "英雄联盟"，"吃鸡" = "和平精英"）。
- **FR-3.2**：`GET /user/discover?keyword=…` 扩展支持：昵称、标签、服务标题、城市；并对 `avatar / nickname` 缺失情况做后端兜底返回默认值，确保前端不出现 undefined 头像。
- **FR-3.3**：`GET /posts?keyword=… / GET /groups?keyword=…` 当 `keyword` 过短（长度 1）时返回空数组 + `meta.ignored=true`，明确告知前端"请输入更多字"，避免性能/误匹配问题。
- **FR-3.4**：搜索接口统一返回 `meta` 字段：`{ tookMs, total, keyword, ignored, reason }` 方便埋点与运营排查。

### FR-4 前端关键页面全量兜底
- **FR-4.1**：以下页面必须覆盖 4 类兜底，缺一不可：首页、发现页、综合搜索、城市选择、订单列表、钱包、个人中心。
  1) **类型收敛**：任何列表必须 `list = Array.isArray(res.data.list) ? res.data.list : []`；任何对象必须 `obj = isObj(data) ? data : {}`。
  2) **未登录降级**：依赖登录态的区域（签到、精英入口、消息、我的交易）在未登录时展示「登录解锁」按钮与说明，不触发 `GET /api/...` 导致 401 再 toast 骚扰用户。
  3) **空态视图**：空服务 / 空动态 / 空订单 / 空钱包账单 都要有图片 + 文案 + CTA（如"去发布"、"去找大神"）。
  4) **接口错误重试**：错误除 toast 外，关键列表提供"点击重试"按钮，且至少保留最近一次参数。
- **FR-4.2**：`聊天页`、`精英付费页`、`发布动态页`、`组局详情页` 需补齐支付/OSS/推送未配置时的可解释 UI（不显示 undefined；改为"服务未配置，请联系客服开通"）。

### FR-5 打包交付闭环
- **FR-5.1 H5**：在 `app/` 下运行 `npm run build:h5`（或 HBuilder X 等效），产出 `app/dist/build/h5/`。校验：
  - 存在 `index.html`、`static/js/`、`static/css/`；
  - `index.html` 中无 `/node_modules/` 路径的资源引用；
  - 首页可被本地 `python/http` 静态服务器拉起（或 `Invoke-WebRequest` 状态 200），资源全部 HTTP 200（抽样 6 个 JS/CSS 文件）。
- **FR-5.2 微信小程序**：在 `app/` 下产出 `app/dist/build/mp-weixin/`，校验：
  - 存在 `app.json / app.js / app.wxss / pages.json / project.config.json`（或小程序所需等价结构）；
  - 页面目录 `pages/*/index.js+index.wxml` 齐全（抽样首页、发现页、搜索页、城市页、订单页、我的页）。
- **FR-5.3**：若本机环境缺少 HBuilder X CLI，使用 `@dcloudio/uni-cli` / `@dcloudio/vite-plugin-uni` 的纯 Vite 命令构建作为等价手段，并在 Review 证据中明确差异与限制。
- **FR-5.4**：构建产物中不得残留 `admin/admin123`、开发密钥等敏感内容；且所有对 `/api` 的引用在 H5 产物中均为相对路径（便于部署到任意域名）。

## 4. 非功能需求（Non-Functional Requirements）
- **NFR-1 性能**：
  - `GET /api/regions/tree` 首次调用响应 ≤ 300ms（34 省+337 市）。
  - 城市搜索 `/api/regions/search` 10 次平均响应 ≤ 100ms。
  - 搜索接口在无 keyword 时不做模糊匹配，直接走正常分页。
- **NFR-2 稳定性**：
  - 任何接口失败，前端页面**不得**出现 `undefined`/`NaN`/空白核心视图；对应 TR 做回归。
  - 定位 4 级流水线在各级抛错时，必须吞异常并进入下一级，不向用户抛 Promise 未捕获。
- **NFR-3 兼容性**：
  - H5：当前项目支持的浏览器基线（主流 Chrome/Safari/微信内置浏览器）通过冒烟。
  - 小程序：构建产物符合 MP 规范（不能含 `document/window` 直引，`uni.*` 替换全部正确）。
  - App：若 HBuilder X 真机打包受限，必须保证 Vue 语法、uni-app API 调用合规，不出现 H5-only 语法（如 `location.href`）。
- **NFR-4 安全**：
  - 新增的定位密钥在配置中心 `app.geoKey` 字段，默认值为空字符串，不在 `.env.example` 中预置。
  - IP 粗定位只返回省/城市名，不对外暴露原始 IP 地址与 headers。
  - `/api/location/reverse` 不输出第三方原始响应，只返回 `{ province, city, district, source }`。
- **NFR-5 可观测**：
  - 后端搜索/定位接口新增 `X-Response-Time` 响应头或日志字段（日志级别 info），包含 tookMs。
  - 前端 4 级定位结果在开发模式下输出 `[Location]` 调试日志（生产模式关闭）。
- **NFR-6 文档同步**：PROJECT.md、README.md、.env.example 三项必须同步更新；PROJECT.md 中必须明确记录城市覆盖度（34 省、≥337 地级及以上城市、数据来源）。

## 5. 约束、依赖、假设、开放问题
- **约束 1**：不引入 MySQL / Redis 等新存储，全国行政区划数据保存在 `server/src/data/china_cities.json`（或 JS 模块），启动时一次加载到内存。
- **约束 2**：关键配置（geoProvider、geoKey）必须为空默认值，通过管理后台配置中心下发；前端在未配置时不能请求外部地图接口造成额外费用。
- **约束 3**：所有功能完成后，需自行运行 Jest 单测 + 接口冒烟；并给出 H5/小程序构建产物存在性与关键文件存在性的证据。
- **依赖 1**：`server/package.json` 若缺少 `pinyin-pro` 等中文→拼音库，可新增；但版本、license 需合规（MIT 优先）。
- **依赖 2**：若地理逆解需要 SDK（如 `@amap/amap-jsapi-loader` 或 node 版），按需引入；不强制，使用 axios HTTPS 即可。
- **假设 1**：用户期望的"企业级运营"至少保证民政 2024 年 34 省 333+4 地级及以上城市的覆盖；不含区县三级。
- **开放问题 1**：区县三级是否需要？**本次规格默认不做**（直辖市下区可当作城市列出，其它不含）；后续可独立 Phase。
- **开放问题 2**：是否需要真的对接高德/腾讯？**规格支持但不强制**；默认"off + IP + 手动"三级可直接上线，运营可在配置中心填 key 打开第 1 级。

## 6. 验收标准（Acceptance Criteria）
AC 类型仅允许 `rule`（可证真/假）或 `rubric`（评分+阈值）。

### rule
- **R-AC-01**：`GET /api/regions/tree` 返回的省级数 == 34，且城市数总和 ≥ 337。
- **R-AC-02**：`GET /api/regions/search?kw=郑州` 返回的第一项城市 `name` 包含"郑州"；`kw=shenzhen`（拼音）能返回"深圳市"；`kw=bjs`（拼音首字母）返回"北京市"。
- **R-AC-03**：配置中心存在 `app.geoProvider` 与 `app.geoKey` 字段；未配置时前端城市页顶部显示"定位服务暂未配置，已切换到手动选择城市"的软提示，且不抛任何异常。
- **R-AC-04**：后端新增 2 条路由 `POST /api/location/reverse`、`GET /api/location/guess-by-ip`；两者在 geoKey 为空时均返回 200 + 合法 `{ province, city }`（guess-by-ip 可返回 `"北京"` 默认值 + `fallback=true`）。
- **R-AC-05**：首页/发现页/搜索页/城市页/订单列表/钱包/个人中心 共 7 页在浏览器 DevTools 里对任一接口 `Block request domain` 后：不抛 JS 未捕获错误；展示空态或"接口失败，点击重试"；页面上不存在"undefined"字符串。
- **R-AC-06**：`services/posts/groups/user.discover` 四个搜索接口均返回 `meta` 字段；当 keyword 长度为 1 时，`posts/groups` 返回 `meta.ignored=true` 且 `data.list=[]`。
- **R-AC-07**：H5 构建 `app/dist/build/h5/` 存在 `index.html` 且包含至少 3 个 `/static/` 相对资源引用；本地起静态服务后 `index.html` 返回 200，抽样 6 个静态资源全部 200。
- **R-AC-08**：微信小程序构建 `app/dist/build/mp-weixin/` 存在 `app.json`、`app.js`、`app.wxss`；且 `pages/home/index.js` 等 6 个核心页文件齐全。
- **R-AC-09**：Jest 12 套件 + 95 用例全部通过（与现有基线一致）。
- **R-AC-10**：`PROJECT.md / README.md / .env.example` 均包含本次新模块的说明（定位策略、打包命令、全国城市数据集版本说明三者任缺即不通过）。

### rubric
- **Rb-AC-01**（可运营性 0-3，阈值 ≥ 2）：
  - 0：城市选择仍只有几十个样本或严重缺省。
  - 1：城市数 ≥ 200 但缺直辖市/特别行政区或字母索引导航缺失。
  - 2：34 省 + ≥337 地级及以上城市；字母索引可用；支持中文/拼音/别名三模搜索。
  - 3：以上全部 + 省→市两级分组的交互可在 3 秒内让非专业用户完成城市切换；且 hotCities 与业务 top 城市真实对齐。
- **Rb-AC-02**（前端兜底与质量 0-3，阈值 ≥ 2）：
  - 0：接口失败仍会白屏/undefined 满屏。
  - 1：部分页面（< 5 个）做了类型收敛与空态；但核心路径仍有明显未兜底处。
  - 2：7 大页面全部满足 FR-4.1 四类兜底；阻断式白屏/undefined 现象消失。
  - 3：以上全部 + 关键列表可记忆滚动位置、错误提示具备"可执行建议"（如"定位失败→去手动选择城市"）。
- **Rb-AC-03**（打包交付完备度 0-3，阈值 ≥ 2）：
  - 0：缺少任一目标端输出目录或目录结构明显残缺。
  - 1：两端产物都在，但未做关键文件存在性校验；或仅一端通过。
  - 2：两端产物 + 关键文件 + 基础资源 HTTP 200 校验都通过。
  - 3：以上全部 + 有体积/资源数量化统计（例如 H5 静态资源 24 个、体积 3.4MB、无 404）。
- **Rb-AC-04**（文档与配置中心一致性 0-2，阈值 ≥ 1）：
  - 0：文档未更新或与代码状态不一致。
  - 1：三项文档更新完整，但缺少配置中心 label/required 等 UI 标注补齐。
  - 2：三项文档完整 + `app.geoProvider / app.geoKey` 在 Settings 界面有中文 label、required/选填标识与描述。
